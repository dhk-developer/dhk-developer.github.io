Why I made it

Some games draw a little burst wherever you tap, and I wanted that on my Windows desktop. It's a fan project and has nothing to do with any game company.

It sounds simple, but it had three rules: it has to cover every monitor, it must never swallow a click meant for another app, and it should cost nothing when you aren't clicking.

How it works

  • A see-through window over everything. A borderless, transparent WPF window covers all monitors and stays on top. Its window style tells Windows to pass every click through to whatever is underneath, and keeps it out of Alt-Tab.
  • Listening for clicks everywhere. A low-level mouse hook notes each left click and hands it to the UI thread. The hook returns straight away, so it never slows down your mouse.
  • Drawing only when needed. Each click spawns a pulse, a spinning arc and a few small shapes. The window only hooks into WPF's per-frame rendering while an effect is on screen, and unhooks when the last one fades.
  • Limits. There are hard caps on how many shapes can exist at once, and rapid clicking makes new bursts smaller instead of piling them up.
  • Light and dark. It reads the Windows theme and uses stronger colours on bright backgrounds.
  • A way out. Ctrl + Alt + Q quits it from anywhere, and there's a tray menu.

Releases

Three small releases (v0.1.0 to v0.1.2), each a change I made after using it for a while: a bigger effect, then automatic light and dark colours.

What I'd change

I'd try a composition-based renderer instead of a full-screen WPF window, so the cost when idle is actually zero, and test properly on monitors with different scaling.

Built with: C#, WPF, Win32 hooks, Custom drawing.
